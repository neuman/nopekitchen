# nopekitchen

The Edmonds kitchen as a nopekit project, published so others can play with the
configurator: **https://neuman.github.io/nopekitchen/marketing/**

A nopekit project: the kitchen, the living room and the upstairs floors, as one model
(`model/kitchen.py`) with a price catalog, checked against a $60k budget and the NKBA
kitchen planning guidelines.

```sh
export PYTHONPATH=<path to nopekit>/src          # github.com/neuman/nopekit
python3 -m nopekit check                         # run the gates
python3 -m nopekit site serve --watch --detach   # the live site
```

- `/engineering/`: the grounding map, each claim and its evidence.
- `/technical.html`: every check and its history.
- `/marketing/`: **the configurator** (`site/marketing/configurator.js`), then the recorded
  design, its story, requirements and decisions. Its data, `site/assets/twin.json`, is
  generated by `views/twin.py` from the model on every `site build`.

Faucets: `CATALOG["faucet"]` in `model/kitchen.py` carries each option's price, its
style (`spring` or `gooseneck`), its stated height and reach, and the configurator
draws the chosen one to those numbers over the sink. Seven spring-coil faucets
(IKEA MAJSJÖN and TAKSJÖN, Kraus Bolden, Delta Antoni and Trinsic Pro, Moen Align,
Kohler Tournant) and three goosenecks are in it; add one by adding a catalog entry.

Build the site with `tools/build_site.sh`, not a bare `nopekit site build`: it runs the
build and then `tools/ground_map.py`, which finishes the grounding map (columns CHOICES,
IMPLICATIONS, CLAIMS; every catalog and yes/no choice swapped through its options so it
has lines; every claim joined to the choices it is about) and fails if anything on the map
is joined to nothing. The map stays a drawing on a phone (`site/engineering/index.html`).

The configurator also has a magnetic knife strip option (`CATALOG["knife_strip"]`), an
"Everyday clutter" layer drawn from the reference photographs (papers, plants, toys: the things
the kitchen keeps are placed by the model instead), and cameras "At the sink"
and "At the prep counter" (`marketing/#cam=sink`, `#cam=prep`).

What the kitchen holds is in `model/inventory.py`: 293 things read on 2026-11-13 from thirteen
photographs of the existing cabinets with every door open (`inputs/20261113-*.json`; the
photographs themselves are kept out of this public repository), each with a typical size and the
parts that draw it. `stow()` in `model/kitchen.py` gives each thing a drawer,
shelf or counter spot in whatever layout is chosen, by rule: chemicals only under the sink, the
children's things low, alcohol and medicine high, one kind in one cabinet, each kind near where
it is first used. Claims C18 to C23 check the plan; A7 says the list is an estimate. The
configurator draws the things in the cabinets, lists them under *Where everything goes*, and its
*Exploded view* slider opens every door and drawer and brings the contents out. The *Cabinet
labels* overlay (off until asked for) tags each drawer, and each cabinet behind its doors, with the
kinds kept there: each kind's `short` name in the inventory. To move a thing,
edit its row in the inventory, or pin it: `stow_pins="thing=place"` in `CONFIG`.

To record a combination from the configurator as the design: press *Copy my configuration*,
put those fields in `CONFIG` at the bottom of `model/kitchen.py` (and in
`selftest/known_good.py` if it should become the reference), and run `nopekit check`.

Prices were read on 2026-11-12 from search-result snippets and store tags. None is a quote.

# the site

`site/` is published by GitHub Pages from `main` (`.github/workflows/pages.yml`).
The configurator loads three.js from a CDN; run `nopekit site vendor` for an offline copy.
